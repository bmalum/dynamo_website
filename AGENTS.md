# AGENTS.md: elixir-dynamodb.dev

Landing page and hosted docs for [Dynamo](https://github.com/bmalum/dynamo), the
Elixir DynamoDB library by Martin Karrer (karrer.solutions). Static files on
Cloudflare Pages, deployed from `main`. No build step for the page itself.

Read this before editing anything. Every trap listed here cost time once.

## What lives where

| Path | Source of truth | Edit directly? |
|---|---|---|
| `index.html`, `styles.css`, `script.js` | this repo | yes |
| `docs/` | ExDoc output of `../dynamo` | **no**, regenerate |
| `skills/` | `../dynamo/skills/` | **no**, regenerate |
| `llms.txt`, `llms-full.txt` | generated by `build-docs.sh` from `../dynamo` | **no**, edit the heredoc in `build-docs.sh` |
| `og-image.png` | rendered from the site's own CSS (see below) | regenerate when design changes |
| `_headers`, `_redirects` | Cloudflare Pages config | yes |
| `sitemap.xml`, `robots.txt`, `manifest.json`, `favicon.svg` | this repo | yes |

The library checkout is expected at `../dynamo`. `build-docs.sh` takes another path as its first argument.

## Rules

1. **Every code snippet on the page must run against the library.** Before publishing a new or changed snippet, put the schemas in a `.exs`, drive them through `Dynamo.TestRepo` + `Dynamo.FakeDynamo` (both in `../dynamo/test/support/`), and execute with `MIX_ENV=test mix run -r schemas.exs check.exs` from `../dynamo`. The 0.1 site documented functions that did not exist; do not let that happen again. `script.js` does not duplicate snippets (the copy button reads the `<pre>`), so there is one place to keep correct.
2. **Design system is karrer.solutions'.** Tokens in `styles.css` `:root`: background `#F8F9FB` → `#F1F3F7`, ink `#0E1A2E`, blue `#2451D6`/`#1A3DA8`, hairline `#DDE2EA`, radius 10 px, amber `#F0B23E` only for the key separator. Sora 700 for headings (tracking −0.042em on h1), IBM Plex Sans body, IBM Plex Mono code. The `.kiro/skills/web-design-anti-slop` rules apply: no eyebrows, no em-dashes, no three-identical-cards, no gradient text, one authored motion (the key composer assembling; CSS-only, respects reduced motion).
3. **No `—`/`–` in visible copy.** Use period, comma, colon. `grep -n "—\|–" index.html` before committing.
4. **Only the hero has hand-marked syntax spans** (`.k .m .a .s`); every other `<pre class="code">` uses Prism with the palette in `styles.css`. Don't mix.
5. **Structured data must match the page.** The FAQPage JSON-LD and the visible FAQ are the same questions; add to both. Keep `softwareVersion` in sync with `mix.exs`.
6. **Backlink to https://karrer.solutions stays** in header brand line, footer, JSON-LD author/publisher and `<link rel="author">`.

## Deploy

```bash
git push origin main        # Cloudflare Pages builds and deploys, ~45 s
```

Then verify, don't assume:

```bash
for u in / /docs/ /docs/dist/html-PVRIOB7F.js /skills/dynamo-elixir/SKILL.md /llms.txt /og-image.png; do
  curl -sL -o /dev/null -w "$u -> %{http_code}\n" "https://elixir-dynamodb.dev$u"; done
curl -s https://elixir-dynamodb.dev/ | grep -o 'styles.css?v=[0-9a-f]*'   # must match local index.html
```

(The `dist/*.js` filename hash changes with ExDoc versions; take the current one from `docs/index.html`.)

### Caching, and why it bit us

Cloudflare cached `script.js`/`styles.css` for a year (`immutable`) while `index.html` changed, so visitors got new HTML with old assets and console errors from the previous site. Now:

- `index.html` references `styles.css?v=<sha8>` and `script.js?v=<sha8>`; `build-docs.sh` recomputes the hashes. **Run `./build-docs.sh` (or its last block) after any CSS/JS edit**, otherwise the edge serves the old file.
- `_headers`: default `max-age=0, must-revalidate`; CSS/JS one day; only images/fonts are `immutable`; `/docs/*`, `/skills/*`, `llms*.txt` five minutes.
- If something still looks stale in a browser, it is the browser: hard reload. Check the server with `curl`, not the browser.

## Regenerating docs, skills, llms.txt

From this repo, with the library at `../dynamo` on the branch you want published:

```bash
./build-docs.sh ../dynamo
```

It runs `mix docs` in the library, copies `doc/` → `docs/` (dropping the epub), copies `skills/`, writes `llms.txt` (index; edit the heredoc in the script) and `llms-full.txt` (README + guides + Agents.md + CHANGELOG + SKILL.md concatenated), and re-hashes the CSS/JS references.

Trap: `.gitignore` used to contain a blanket `dist/`, which silently excluded `docs/dist/` (all ExDoc CSS/JS). It is now `/dist/` (root-anchored). If docs render unstyled after a deploy, check `git ls-files docs/dist | wc -l` first.

## Regenerating the OG image

The OG image is the real design, not an illustration. Recreate `og.html` with the site's `styles.css` and the composer markup at 1200×630 (the previous version is in git history of this file's commit `f0ffb8a` if you need the template), then:

```bash
python3 -m http.server 8765 & sleep 1
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1200,630 --virtual-time-budget=5000 --screenshot=og-image.png http://localhost:8765/og.html
kill %1; rm og.html
```

## Visual check before pushing

Headless Chrome for desktop, Firefox for mobile (Chrome's mobile emulation via `--window-size` mis-renders some CSS animations here):

```bash
python3 -m http.server 8765 & sleep 1
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1440,7800 --virtual-time-budget=4000 --screenshot=/tmp/full.png http://localhost:8765/
"/Applications/Firefox.app/Contents/MacOS/firefox" --headless --window-size=390,2600 --screenshot /tmp/mobile.png http://localhost:8765/
kill %1
```

Look at both. Check: no horizontal overflow, code blocks scroll rather than clip, the key composer shows both keys, nothing reads as a template.

## Things that are deliberately not here

- No analytics. Add only with a cookie-free provider and update the CSP in `_headers`.
- No German version. Dynamo's audience is the international Elixir community; karrer.solutions' brand file allows English for developer-facing material.
- No shared component package with `karrer.sites` yet: that repo's `packages/ui` is empty and `CHOSEN.md` has no direction. When it exists, this site is a token rename away.
